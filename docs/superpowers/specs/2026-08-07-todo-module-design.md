# Дизайн: модуль «Список дел» с прогресс-баром

Дата: 2026-08-07. Статус: утверждено владельцем продукта.

## Задача

В преддверии переезда семья ведёт общий список дел. Нужен модуль «Список дел»: обычный todo-лист с прогресс-баром. Прогресс-бар — только для этого модуля; общий CRUD-интерфейс других модулей не меняется.

## Продуктовые решения (утверждены)

- Универсальный модуль «Список дел» (пригодится и после переезда), а не специализированный «Переезд».
- Плоский список: дело = текст + необязательные заметка и дата + галочка «сделано». Без категорий и без назначения ответственных.
- Дата — просто дата-пометка, без подсветки просроченного.
- Прогресс-бар один общий: процент выполненных дел.
- Доступ: семья (общая группа) видит и меняет список; гости с «только чтение» — видят список и прогресс без права изменений.

## Поведение страницы

- Сверху — заголовок модуля, под ним прогресс-бар: «N из M сделано», полоса заполняется по проценту. При 100% — состояние «Всё сделано». При пустом списке — «Пока нет дел».
- Порядок списка: невыполненные сверху, выполненные внизу. Внутри групп: по дате по возрастанию, дела без даты — после датированных, при равенстве — по id.
- Состояния: загрузка, ошибка (с повтором), пустой список, read-only (без форм и кнопок изменения).

### Добавление дела

- Над списком — форма добавления: текст дела (обязательно), необязательные заметка и дата, кнопка «Добавить».
- Сохраняется без перезагрузки страницы (`POST`), новое дело сразу появляется в списке сверху (невыполненные), прогресс-бар пересчитывается. Форма очищается и остаётся готова к следующему вводу.
- Пока запрос выполняется — кнопка «Добавить» заблокирована; при ошибке — сообщение и прежнее содержимое формы (ввод не теряется).

### Редактирование и удаление дела

- У каждого дела кнопка «Изменить»: разворачивает инлайн-форму с текстом, заметкой и датой, кнопки «Сохранить»/«Отмена». Сохраняется без перезагрузки (`PATCH`), список и прогресс обновляются. Ошибка сохранения не теряет введённое.
- У каждого дела кнопка «Удалить»: сначала подтверждение («Удалить дело? Действие необратимо»), затем удаление (`DELETE`), дело исчезает, прогресс пересчитывается.
- Галочка «сделано» — отдельный переключатель: один клик сохраняет состояние (`PATCH`) без открытия формы; выполненное дело сразу уходит вниз.
- Пока выполняется любой из этих запросов, повторные действия по этому делу заблокированы.

## Данные

Сущность `task` (одна) в `modules/todo/manifest.json`:

| Поле | Тип | Обязательное | Назначение |
| --- | --- | --- | --- |
| `title` | text | да | Текст дела |
| `note` | textarea | нет | Заметка |
| `when` | date | нет | Дата-пометка |
| `done` | boolean | нет | Сделано/не сделано |

`defaultSort`: по полю `done` asc (невыполненные первыми на сервере; на странице дополнительная сортировка по дате — клиентская).

## Архитектура

- **Бэкенд — простой модуль** (`kind: "simple"`, только `manifest.json`). Существующий CRUD-генератор даёт таблицы, валидацию полей, проверку прав через `core.can` и CSRF бесплатно. Нового серверного кода нет.
- **Интерфейс — свой React-компонент** в пакете модуля `modules/todo/` (образец — `modules/admin/`): `src/ui.tsx` + `src/ui.css`, сборка через `tsc` + копирование css. Компонент использует те же REST-эндпоинты CRUD (`/api/modules/todo/task`).
- **Реестр интерфейсов** (`apps/web/src/modules/registry.tsx`): карта `CODE_UI` получает запись `todo`; `resolveModuleUi` отдаёт кастомный UI при наличии записи, иначе — прежнее поведение (`CrudModule` для simple). Так интерфейс переопределяется только у этого модуля.
- **Доставка интерфейса**: web добавляет зависимость `@perepelkin-home/module-todo` и лениво импортирует `@perepelkin-home/module-todo/ui` (как сейчас статически импортируется `module-admin/ui`).

## Затрагиваемые слои

- `modules/todo/`: `manifest.json`, `package.json`, `tsconfig.json`, `src/ui.tsx`, `src/ui.css`, `scripts/copy-css.mjs`.
- `apps/web/src/modules/registry.tsx`: регистрация UI модуля.
- `apps/web/package.json`: зависимость на `@perepelkin-home/module-todo`.
- Корневой `package.json`: скрипты `build` и `dev` — сборка `module-todo` перед web.
- `Dockerfile`: копирование `modules/todo/package.json` (build и runtime стадии), копирование `dist` и `manifest.json`.
- `README.md`: раздел про модули со своим интерфейсом.
- `apps/server/test/repo-modules.test.ts`: проверка, что модуль `todo` монтируется и проходит CRUD (create → toggle done → list → delete).

## Проверка

- Автотесты: манифесты из `modules/` валидны (существующий safety-net); CRUD модуля `todo` работает (новый тест).
- Ручная проверка (Playwright, скилл `webapp-testing`): добавить дело → прогресс-бар меняется; отметить одним кликом → дело уходит вниз, прогресс обновляется; удаление с подтверждением; гость с «только чтение» видит список и прогресс без форм изменения.
- `npm run typecheck` и `npm run build` проходят.

## Вне объёма

- Категории/разделы, назначение ответственных, сроки с подсветкой — не делаем.
- Прогресс-бар в общем CRUD-интерфейсе — не делаем.
- Полноценный серверный плагин код-модуля — не нужен, бэкенд остаётся декларативным.
