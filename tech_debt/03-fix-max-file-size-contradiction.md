# [P1] Устранить противоречие MAX_FILE_SIZE_MB (код vs env.example vs README)

## Приоритет: Высокий
## Оценка: 1/10 (5 минут, правка константы + документации)
## Файлы: `apps/server/src/config.ts`, `apps/server/.env.example`, `.env.example`, `README.md`

## Проблема

Три разных значения для дефолта/максимума:

| Источник | Дефолт | Максимум |
|----------|--------|----------|
| `config.ts:54` | 256 MB | 256 MB |
| `apps/server/.env.example:17` | 8 MB | — |
| `README.md:132` | 8 MB | 64 MB |
| `.env.example:19` | 8 MB | 256 MB |

Пользователь не знает, какое значение реальное. Код дефолтится в 256 MB, но документация говорит 8 MB / макс 64.

## Что сделать

1. **Принять решение:** дефолт = 8 MB, макс = 256 MB (разумный баланс для домашнего use-case с видео).
2. **Изменить `config.ts:54`:** `parseFileSizeMb(env.MAX_FILE_SIZE_MB, 8)` — дефолт 8.
3. **Обновить `config.ts:55`:** лимит максимума — `Math.min(parsed, 256)` (уже есть).
4. **Обновить `README.md:132`:** "размер по умолчанию до 8 МБ (`MAX_FILE_SIZE_MB`, максимум 256)".
5. **Проверить оба `.env.example`:** оставить `MAX_FILE_SIZE_MB=8` в обоих (дефолт, явно).

## Подводные камни

- Если кто-то уже использует дефолт 256 MB без env-файла, изменение дефолта на 8 уменьшит максимально допустимый размер загрузки. Это **breaking change** для таких пользователей. Решение: в README написать "если нужны видео > 8MB, установи MAX_FILE_SIZE_MB=256".
- README также неверно утверждает "только изображения" — код разрешает `video/mp4`, `video/webm`, `video/quicktime`. Исправить README: "Изображения и видео (jpeg, png, webp, gif, avif, mp4, webm, quicktime; SVG запрещён)".

## Валидация

- `npm run typecheck`
- Проверить что `config.test.ts` (если есть) не падает
- Ручная провера: без env-файла → дефолт 8 MB; с `MAX_FILE_SIZE_MB=300` → 256 MB (clamped)
