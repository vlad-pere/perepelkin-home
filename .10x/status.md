# Статус проекта

Фаза: **Реализация (module-system, TDD)**.

- `module-system` этап 1 — **завершён**: контракт манифеста + `CoreApi` в `packages/core`, сервер переведён на `Core extends CoreApi`.
  - `validateManifest`/`ManifestError`/типы манифеста: `packages/core/src/manifest.ts` + 25 RED-тестов (`manifest.test.ts`).
  - `CoreApi`: `packages/core/src/api.ts`; платформенные секреты (`passwordHash`, мутации) убраны из публичной поверхности — `apps/server/src/core.ts`, `routes/admin.ts`.
  - Примечание к TDD: TS 5.9 не сужает тип через never-call, если бросающая функция — `const`-стрелка; `fail` объявлен как function declaration.
  - Сборка: `npm run build`, `npm run typecheck`, `npm test` — всё зелёное (35 core + 27 server).
- `module-system` этап 2 — **завершён**: схема v2 в `apps/server/src/db/db.ts` (миграция 2): таблицы `modules`, `module_migrations` (FK cascade). Тесты `test/db.test.ts` (5): создание, колонки/CHECK, cascade, идемпотентность reopen, апгрейд v1→v2 с сохранением данных. Все 32 server-теста зелёные.
- `module-system` этап 3 — **завершён**: хост модулей.
  - `apps/server/src/modules/host.ts`: `mountModule` (prefix `/api/modules/<id>`, гард `makeModuleGuard` на `read`/`write`, `GET /manifest`), `syncModule` (upsert + `module_migrations` + entity-таблицы; версия растёт только при изменении манифеста), `registerModulesFromDisk` (изоляция битых: `status='broken'`, остальные работают; avvio не отравляется — ошибка регистрации не попадает в boot), `ModuleContext.route` для код-модулей.
  - `apps/server/src/modules/crud.ts`: генератор CRUD из манифеста (валидация типов/required, `defaultSort`, boolean↔0/1, `created_by`).
  - `apps/server/src/modules/loader.ts`: чтение `manifest.json` из подкаталогов.
  - `Config.modulesDir` (env `MODULES_DIR`), `createApp` монтирует модули из каталога.
  - Тесты `test/host.test.ts` (16): 401/403, read-only гард, CRUD-цикл, валидация payload'ов, сортировка, `ctx.route`, sync/version, изоляция битых.
  - Найденное при TDD: avvio «отравляет» boot при падении плагина — ошибка регистрации ловится внутри плагина и всплывает в `mountModule`.
  - Все 48 server-тестов + typecheck + build зелёные.
- `module-system` этап 4 — **завершён**: фронт-реестр и авто-CRUD простых модулей.
  - `apps/web/src/modules/registry.tsx`: `ModuleApiClient`/`ModuleUiProps`/`resolveModuleUi` (simple → `CrudModule`, code → `CODE_UI`), `ModuleUnavailable`.
  - `apps/web/src/modules/CrudModule.tsx` + `crud.css`: секции сущностей, формы create/edit, удаление с подтверждением, состояния загрузка/пусто/ошибка, все типы полей (text/textarea/number/date/boolean).
  - `apps/web/src/App.tsx`: маршрут `/m/:moduleId/*` с guard по `me.modules` и защитой `/admin` (редирект на `module.route`); `Home.tsx` — ссылки из `module.route` (жёсткий словарь удалён).
  - `packages/core`: `ModuleAccess` расширен `kind`/`route`; `buildMe` читает kind из таблицы `modules`.
  - Тесты: 2 новых `/me` (kind/route для admin и simple) — 50 server-тестов зелёные.
  - Runtime-проверка (webapp-testing, Playwright): вход, Home, CRUD-цикл, read-only для гостя без кнопок; ожидаемый 401-шум от анонимных `/api/auth/me` отфильтрован; визуальный детектор impeccable — `[]`.
- `module-system` этап 5 — **завершён**: инвалидация сессий.
  - `apps/server/src/db/sessions.ts`: `deleteSessionsForUser`; `apps/server/src/core.ts`: `resetPassword` и `setAdmin(false)` инвалидируют все сессии пользователя (сброс пароля — обязателен: CSRF-токен живёт в сессии, иначе украденные куки переживают сброс; снятие админа — продуктовое решение «выкинуть из системы»).
  - Фронт: `apps/web/src/api.ts` — на 401 `UNAUTHENTICATED` (когда csrf-токен был установлен, т.е. сессия реально умерла) редирект на `/login`; анонимный старт не задевается.
  - Тесты: 3 новых в `admin.test.ts` (сброс пароля инвалидирует все сессии двух клиентов + работает только новый пароль; снятие админа инвалидирует сессии; чужие сессии не затрагиваются) — 53 server-теста.
  - E2E (Playwright): новый флоу — админ сбрасывает пароль, следующее действие пользователя уводит на `/login`, вход с новым паролем работает; найдена и убрана гонка в E2E (проверка списка сразу после манифеста, без ожидания данных сущности).
- `module-system` этап 6 — **завершён**: эталонный простой модуль `maintenance`.
  - `modules/maintenance/` — workspace `@perepelkin-home/module-maintenance` + `manifest.json` (kind `simple`; entities `item` — title/nextDue/cost/done с `defaultSort` по nextDue, `note` — text textarea). Модуль появляется одним манифестом, без правки кода ядра/оболочки.
  - Safety-net тесты `test/repo-modules.test.ts` (2, TDD RED→GREEN): реальный каталог `modules/` загружается без ошибок и содержит эталон; эталон монтируется из диска и проходит CRUD-цикл.
  - E2E (Playwright, `MODULES_DIR=../../modules`): реальный модуль из `modules/` — вход, Home, CRUD на `/m/maintenance`, сброс сессии, read-only для гостя; `all flows ok, no browser errors`.
  - Проверки: 35 core + 55 server тестов, `npm run typecheck`, `npm run build` — зелёные.
- **Закрыт отложенный риск коллизий манифеста**: `validateManifest` теперь ловит коллизии имён сущностей и полей без учёта регистра (`Item`/`item`, `titleData`/`titledata`). TDD: 2 RED-теста → `seenEntities`/`seenFields` и defaultSort-проверка на `toLowerCase()`. 27 core-тестов зелёные.
- **Админ-UI групп и грантов — завершён** (этап 2 задачи «сделай все 4 пункта»).
  - `modules/admin/src/ui.tsx`: вкладки «Пользователи»/«Группы»/«Доступы к модулям». Группы: создание/удаление, добавление и снятие участников; доступы: чипы «Чтение»/«Запись» по группам (PUT/DELETE грантов, отзыв при снятии обоих). Дизайн — в языке проекта.
  - E2E (Playwright, `e2e_admin_ui.py`): создание группы через форму, участники (добавить/убрать), гранты read→rw→write→revoked с проверкой по API, видимость модуля у пользователя без группы; `all admin ui flows ok, no browser errors`.
  - Проверки: typecheck + 37 core + 55 server тестов + `npm run build` — зелёные.
- **Прод-деплой Docker Compose + Caddy — завершён** (этап 1 задачи «сделай все 4 пункта»).
  - `Dockerfile` (мультистейдж build/runtime, не-root `node`, `npm ci --ignore-scripts` — prebuilds better-sqlite3 + esbuild optionalDependencies, компилятор не нужен), `docker-compose.yml` (app с healthcheck по `/api/auth/me` + caddy c авто-HTTPS), `Caddyfile`, `docker-entrypoint.sh` (seed → сервер; seed идемпотентен), `.dockerignore`, корневой `.env.example`.
  - Хост-маунт `./modules:/app/modules:ro` — добавление простого модуля без пересборки образа; импорт код-модуля `admin` изолирован от маунта (реальный каталог в `node_modules`, не симлинк).
  - Smoke (Docker на Windows): build образа → `docker compose up` → вход админом, CRUD maintenance с CSRF (403 без токена), read-only гард для гостя (403), статика SPA + SPA-fallback, админ-API групп, персистентность через рестарт (данные и seed-идемпотентность на месте). Docker-стенд остановлен, volumes удалены.
- Отложено: `core.bus`/события — вместе со сценарием напоминаний (без переделки).
