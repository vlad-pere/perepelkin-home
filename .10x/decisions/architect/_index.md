# Архитектор — индекс решений

## Принципы (сквозные)

- **Модульный монолит.** Один Node-процесс, одна SQLite-БД, масштаб до ~100 пользователей. Модули изолируются границами в коде (манифест + хост), а не процессами.
- **Хост — единственная точка монтажа модулей.** Модуль не может объявить эндпоинт без `core.can(moduleId, action)`: простые модули получают роуты от CRUD-генератора, код-модули — только через `ctx.route(action, …)`.
- **Простой модуль = только манифест.** Никакого кода; сервер хранит и отдаёт манифест авторизованному UI → добавление простого модуля не требует пересборки фронтенда.
- **`/me` — источник реестра на фронте.** Оболочка строит главную и доступность модулей из ответа; хардкод модулей в оболочке запрещён.
- **Платформа ≠ модуль.** `/api/auth/*` и `/api/admin/*` остаются платформенными (глобальные `requireAuth`/`requireAdmin`); admin числится код-модулем в реестре только для отображения.
- **Безопасность приоритетнее удобства:** сессии инвалидируются при сбросе пароля и снятии админа; CSRF-токен на сессию; обязательная проверка прав на бэкенде для каждого эндпоинта.
